# Random music

Сайт со случайной музыкой и общим чатом: **https://randommusic.insomnia247.nl**

Заходишь — сразу играет случайный трек из библиотеки на сервере. Кнопка
RANDOM переключает на следующий. Под плеером — анонимный чат без
регистрации. Работает с 2019 года.

![Random music](https://user-images.githubusercontent.com/31764930/116309931-113a9000-a7b2-11eb-83c8-f75d9e45c531.png)

## Версия 2.0

Проект переработан в июле 2026 года. Облик сохранён намеренно — тёмный
фотофон, оранжевый `#f4511e`, системный гротеск, узкая центральная колонка.
Изменилась реализация.

| | v1 | v2 |
|---|---|---|
| Выбор трека | обход трёх каталогов `opendir()` на каждый клик (~4900 файлов) | индекс в SQLite, выборка за 36 мс |
| Метаданные | клиент повторно скачивал mp3 ради ID3-тегов | `ffprobe` при сканировании, теги приходят с треком |
| Чат | `messages.json`, окно в 50 сообщений, остальное терялось | SQLite, полная история, поиск, модерация |
| Антиспам | reCAPTCHA без серверной проверки, то есть никакой | лимиты, honeypot, подписанный токен, стоп-правила, теневой бан |
| Обновления чата | опрос раз в 2 секунды всегда | адаптивный интервал, остановка в скрытой вкладке, ETag → 304, одна вкладка на все |
| Громкость | как записано, разброс 15 дБ между треками | выравнивание по EBU R128 через WebAudio |
| Зависимости фронта | jQuery, html5media, id3.js, reCAPTCHA — 4 внешних узла | ноль, нативные ES-модули |
| Кэш ассетов | месяц без версионирования | год с версией в адресе |
| Бэкапы, git | нет | ежедневные снимки, репозиторий |

Подробности — в истории коммитов ветки: каждый этап отдельным коммитом
с описанием того, что и почему менялось.

## Стек

PHP 8.2 без фреймворка, SQLite, нативные ES-модули. **Ни одной внешней
зависимости в рантайме** — приложение поднимается из чистого `git clone`,
без Composer и без сборки. Так проект остаётся тем, чем был: открыл в
редакторе и за десять минут понял целиком.

* Apache 2.4 + `.htaccess` (роутинг, сжатие, CSP, кэш)
* SQLite в режиме WAL — индекс медиатеки и чат
* `ffprobe` / `ffmpeg` — теги и замер громкости
* `systemd --user` — сканирование, замер громкости, обслуживание, бэкапы
* PWA: манифест, service worker, Media Session

## Возможности

**Плеер.** Случайная выдача с весами, предзагрузка следующего трека,
перемотка, выравнивание громкости, история сессии, постоянная ссылка на
трек с OpenGraph-превью, управление из шторки уведомлений, горячие клавиши,
тема день/ночь. Без JavaScript отдаётся один трек в обычном `<audio>`.

**Чат.** Полная история с подгрузкой вверх, счётчик онлайн, цвета ников,
кликабельные ссылки, сохранение имени. Многослойный антиспам без внешних
сервисов. Модераторская: удаление, баны, теневые баны.

**Библиотека.** 3887 треков, ~254 часа. Индекс обновляется каждые 15 минут,
подхватывая загрузки из Telegram-бота. Дедупликация по хешу, полнотекстовый
поиск, восстановление кириллицы в тегах ID3v1, статистика прослушиваний с
пересчётом весов ротации.

## Структура

```
apps/randommusic/          код, вне веб-корня
├── src/                   приложение (App\*, PSR-4 без composer)
│   ├── Kernel.php         роутер и точка входа
│   ├── Track/             индекс, сканер, статистика
│   ├── Chat/              хранилище, антиспам, модерация
│   ├── Http/              запрос, ответ, шаблоны
│   └── Support/           конфигурация, БД, кэш, клиент
├── templates/             PHP-шаблоны
├── migrations/            SQL-миграции по базам
├── bin/                   CLI: scan, loudness, migrate, backup, deploy…
├── public/                то, что уезжает в веб-корень
├── deploy/systemd/        таймеры systemd --user
├── var/db/                chat.sqlite, tracks.sqlite (не в git)
└── legacy/v1/             снимок первой версии

docroot/
├── index.php  .htaccess  assets/     из public/
└── 1000/ music/ upload/              симлинки на медиатеку
```

Код лежит **вне** веб-корня: исходники и базы недостижимы по HTTP
физически, а не по договорённости с `.htaccess`.

## Запуск

```bash
cp .env.example .env && chmod 640 .env   # заполнить ADMIN_TOKEN и CLIENT_SALT
bin/migrate                               # создать базы
bin/import-legacy                         # перенести чат из messages.json, если он есть
bin/scan --full                           # обойти медиатеку (~6 мин на 3900 файлов)
bin/loudness --all                        # замерить громкость (~30 мин)
bin/deploy staging                        # выложить в /v2 для проверки
bin/deploy prod                           # выложить в корень (снимет бэкап)
```

Требуется PHP 8.2 с `pdo_sqlite` и `mbstring`, плюс `ffmpeg`/`ffprobe`.

### Эксплуатация

| Команда | Что делает |
|---|---|
| `bin/scan` | Инкрементальный обход медиатеки (секунды) |
| `bin/loudness` | Замерить громкость партии треков |
| `bin/fix-encoding` | Починить кириллицу в тегах ID3v1 |
| `bin/maintenance` | Чистка таблиц, пересчёт весов, WAL |
| `bin/backup` | Снимок баз |
| `bin/deploy prod` | Выкатка с автоматическим бэкапом |
| `bin/cleanup-v1` | Убрать мёртвый код первой версии |

Таймеры `systemd --user`: сканирование каждые 15 минут, замер громкости
каждые 30, обслуживание и бэкап ежедневно.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/track/random?exclude=1,2,3` | Случайный трек с тегами |
| `GET` | `/api/v1/track/{id}` | Метаданные трека |
| `GET` | `/api/v1/track/search?q=` | Поиск (FTS5) |
| `POST` | `/api/v1/track/{id}/event` | `event=played\|skipped`, `listened=сек` |
| `GET` | `/api/v1/chat?since={id}` | Инкрементальная лента (ETag → 304) |
| `POST` | `/api/v1/chat` | `name`, `content`, `token`, `website` (honeypot) |
| `GET` | `/api/v1/chat/history?before={id}` | Подгрузка истории вверх |
| `GET` | `/api/v1/stats` | Сводка |
| `GET` | `/api/v1/health` | Состояние для мониторинга |

Адреса первой версии — `/messages.json`, `/getfile.php` и `POST /` —
продолжают работать: у части посетителей вкладка открыта неделями.

Модераторская: `/admin?token=<ADMIN_TOKEN>`.

## Заметки

* Все URL относительные, домен нигде не захардкожен: переезд сводится к
  копированию папки.
* `.env` должен быть `640`. При `600` его читает только CLI, а веб берёт
  умолчания и подписывает токены формы известной строкой. Состояние
  конфигурации видно в `/api/v1/health`.
* Веб работает под отдельным пользователем, CLI — под владельцем файлов,
  оба в одной группе. Каталоги `var/*` имеют setgid, приложение выставляет
  `umask(0002)`.
* Музыка не входит в репозиторий.

Связанный проект — Telegram-бот сообщества
[@randommusic_reborn](https://t.me/randommusic_reborn): по команде
`/upload` кладёт присланный трек в каталог, который сайт подхватывает
следующим сканированием.
